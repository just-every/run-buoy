# Search native customer records

Signed-in staff can call `GET /api/buoy/search?q=customer.example` with the same session used to read accounts. This is a JSON API; there is no search screen yet.

One literal substring query searches current account names and IDs, renewal/billing/support reference text, current account custom and calculated values, customer contact/user names and IDs and current custom/calculated values, and approved task titles, IDs, completion outcomes and evidence. A domain, email or external ID recorded as a custom field is searchable as text; search does not create an identity mapping or claim to have connected Salesforce. SQLite's `lower` makes ASCII letters case-insensitive; other characters match literally. Percent, underscore, quotes and backslashes are ordinary characters, not wildcard or query syntax. Field names and historical values are not searched.

`q` is required, trimmed, at most 200 characters and contains no control characters. `limit` is 1–100, default 50. Results sort by kind then native ID and include `kind`, `id`, `title`, current `accountIds`, a matching text `excerpt` and a signed-in native `href`. A person with several account memberships appears once. `nextCursor` resumes after the last result; send the same `q` and the opaque cursor to retrieve the next page. Pages read live data rather than a frozen snapshot: edits and erasures take effect on the next request. Missing or malformed inputs return 400; no matches returns an empty result list and null cursor.

Owner, admin and member sessions have today's ordinary account/customer read access. Anonymous and agent requests are refused by the existing HTTP/session and command boundaries; search grants no new authority. Credentials, authentication records, another person's inbox, raw usage intake/review queues and earlier/erased snapshots are outside this search corpus. Results read the native tables directly, so there is no stale search index to retain erased data.

ACCOUNT-005 remains partial. The full requirement still includes native search UI, timeline/email bodies, plans, opportunities and later custom-object kinds, connected Salesforce identities, ROLE-001 scoped read-only/field permissions and the original 5,000-account, one-second acceptance. This slice does not establish those capabilities or performance bounds.
