# Synthetic ChurnZero account mapping example

`accounts.csv` is a synthetic twenty-account CSV for the explicit column mapper. The headers are an example mapping contract, not a verified ChurnZero export schema. No customer export or versioned vendor schema was supplied. Select and review the actual headers from your export; the mapper never guesses them or supplies missing contract terms.

The fixture has explicit account identities, names, renewal dates, notice periods, contract references and invoice snapshots. `ChurnScore` and `ChurnScore Factors` can be explicitly mapped to a read-only native account observation using `churnScore` and `churnScoreFactors`. The example contains scores 4 through 80, a usage factor 1 through 20 and an engagement factor 19 through 0. No weights, bands or scoring rules are inferred. `Journey` and `Contact` remain unmapped source columns. Their values remain in the retained original CSV; review names each unsupported column for each source account. These observations create no customer people or runnable journeys. In particular, retained journey labels are not paused Buoy journeys and establish no steps or execution authority.

MIGRATE-002 stays partial. Native contacts, vendor scorecard-definition mapping, tasks, plays, success plans, complete journey conditions and assignment semantics, events, NPS, API intake for those record kinds and full source-schema verification remain required. Account API preparation and structured JSON intake retain unsupported collections and explicitly count them, as documented in `docs/migrations.md`. These bytes are used only for deliberate review or tests and are never imported automatically.

An explicitly selected definition column can additionally create read-only paused journey review drafts, as documented in `docs/migrations.md`. The synthetic definition shape is in `tests/churnzero-journey-fixture.mjs`; it is not a verified vendor schema. An unstructured definition keeps every execution behavior explicitly unmapped, with no activation or execution authority. The original account fixture deliberately keeps its Journey label unmapped.

The optional churnzero-journey-v1 preparation envelope now maps the documented public REST definition entities into native paused milestone, task-template and achievement structure. See `docs/migrations.md` for its explicit parent joins, fields and boundaries. Its fixture remains synthetic. This verifies selected field semantics from the public reference, not the customer's source schema, unavailable predicates, progress records or complete migration.
